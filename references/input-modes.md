# 输入模式与资产链路（v3.6 / v3.8 · S0 判定，S3 执行）

> **本文件是「用户手上有没有素材」这件事的唯一权威定义。** 所有 `references/` / `assets/` / `scripts/` 与 `SKILL.md` 里出现「已有资产图 / 裁切 / 从零生成 / 输入槽位 / 精简模式」的地方，都以本文件为准。
> 适用阶段：**S0 判定并写进状态 → S1 决定模型分工 → S3 按模式出提示词 → S5 决定视频参考槽位**。
> 取代 v3.5 的两处错误前提：①「精简模式只在用户明确要求时启用」；②「面部特写与服装图从用户已有资产图裁切、不生成」。

---

## 0. 一句话原则

**输入模式只决定「前两格素材怎么来」，不决定最终交付什么。**

不管用户手上有没有图，**最终人物资产恒定**：每位角色 1 张 `ROLE_SHEET_X` 上下分区定妆板（上 1/3 左正面 + 右侧面面部特写；下 2/3 左放大裁头正面服装图 + 右完整背面全身），出图提示词逐字采用用户定稿（v5.2）；三种输入模式只决定**传哪张参考图**（M1/M2 用已有角色图、M0 用从零生成的 `ROLE_STILL_X` 当「参考形象」），版式逐字不变，`FABRIC_DETAIL_X` 按需、默认不出；`ROLE_SHEET_X` 是**唯一最终人物资产**。**v3.8 起视频层人物参考改为两类成对**：`@ROLE_SHEET_X` 四视图资产 + `@FACE_CLOSE_X` 人脸特写，后者是唯一允许与拼板一起进视频上传序列的过程件（见 §4.2）。三条铁律、色场占比、LUT、生成条规划、成果二分交付**全部不变**。**v3.7 起提示词语言也不随输入模式变化**：`M0` 的 `B-Z` 生成组、`M1` 的补齐组、`M2` 的裁切说明与 `B02` 最终拼板，正文一律简体中文，只有平台参数行、资产 ID、器材型号与单位色值、模型专有名保留原文。

> 这条原则解决的是「skill 只适配一次项目」的问题：有的用户已有 3 张资产图，那是 **M2**；但绝大多数用户只有一个主题、一张图都没有，那是 **M0**，也必须能一路做到成片。不能把 M2 的裁切步骤写成通用规则。

## 1. 三种输入模式

| 模式 | 代号 | 用户手上有什么 | 判定依据 | 出现频率 |
|---|---|---|---|---|
| **零素材** | `M0` / `zero` | **只有主题文字**（可能补时长、画幅、调性） | `assets/` 无人物图，用户也没上传 | **默认、最常见** |
| **部分素材** | `M1` / `partial` | 只有半套：脸图、服装图、风格参考图、或某个角色有图另两个没有 | 有图但凑不齐「面部 + 服装」两格 | 常见 |
| **已有资产** | `M2` / `provided` | 定妆照 / 三视图 / 面部特写 + 服装图，且逐位角色齐备 | 每位角色都能裁出面部与服装两格 | 少数（本次项目） |

**附加情形**：若素材是真人肖像、既有 IP、品牌角色，先提示用户自行确认权利来源与可改动范围，再按 `M2` 处理；提示词里把「禁止改变可识别特征」写进正向约束，不套用「三处记忆点 / 差异化清单」去改人家的脸。不得直接商用第三方素材。

### 1.1 判定动作（S0 必做，但不阻塞）

1. 扫项目 `assets/` 目录，列出已有图片文件；同时看当前会话是否有用户上传图片。
2. 在 `master_overview.md` 的「输入盘点」表里逐位角色打勾：有面部？有服装？有全身？
3. 顺带问一句「有没有人物参考图要接入？」——**用户不回答就按 `M0` 继续**，不追问、不卡阶段、不把「没图」当成缺项去反复确认。
4. 把 `input_mode` 写进 `stage_state.json`（`stage_state.py init/set --input-mode`）与 `generation_plan.json` 的 `asset_policy`，后续阶段只读这个字段。

> S0 禁止出现模型名与提示词，但**允许**出现「输入模式、有哪些素材、缺哪些要从零生成」——这是美学设定与工作量判断，不是工具参数。

### 1.2 部分素材的补齐规则

| 缺什么 | 怎么补 |
|---|---|
| 有脸图、没服装图 | 脸图裁 `FACE_CLOSE_X`（不重画）；`OUTFIT_X` 按 `ROLE_CHARTER_X` 服装六维从零生成 |
| 有服装图、没脸图 | 服装图裁 `OUTFIT_X`；`FACE_CLOSE_X` 按 `ROLE_CHARTER_X` 五官骨相段从零生成 |
| 三个角色里只有一个有图 | 该角色走 M2、其余走 M0，逐角色记录模式，不为了统一而把已有图丢掉重画 |
| 只有风格参考图（不是具体人物） | 判为 `M0`，风格图只作 `VISUAL_MASTER_01` 的调性来源，**不提供身份**，也不算 `FACE_REF_01` |

用户已有图进提示词时逐项写 `inherit-nothing-else`：脸图只提供五官骨相与妆造、服装图只提供形制面料与配饰，其余（身形、比例、光线、背景、色场）一律不继承。

## 2. 资产链矩阵（核心表）

`X` = 角色代号 A/B/C。标 ✅ 的才进视频上传序列。

| 层 | 资产 | `M0` 零素材 | `M1` 部分 | `M2` 已有 | 上传 |
|---|---|---|---|---|---|
| 文字设定 | `ROLE_CHARTER_X` | **必写**（S0 定稿，S3 逐字复制） | **必写**（补齐缺的那一半） | 可略，但建议从图反写一版锁定描述串 | ❌ 不是图 |
| 概念基调 | `CHARACTER_MOOD_X` | 建议 1 张（基调模型，定脸型气质 / 妆造 / 面料方向） | 只在缺的那一半出 | 不出，人物已有 | ❌ |
| 面部格 | `FACE_CLOSE_X` | **生成**（人物模型，出 4 挑 1 锁定） | 有→裁切；无→生成 | **从新版 ROLE_SHEET_X 上方左格裁出（v5.2）** | ✅ **与拼板成对上传（唯一例外）** |
| 服装格 | `OUTFIT_X` | **生成**（人物模型或基调模型） | 有→裁切；无→生成 | **裁切，不生成** | ❌ |
| 稳定锚 | `ROLE_STILL_X` 定妆照 | **建议生成 1 张**（把脸 + 服装先锁在同一张全身图上） | 建议 1 张 | 可选；用户已给定妆照就直接复用 | ❌ 过程锚 |
| **最终** | **`ROLE_SHEET_X` 上下分区定妆板** | **生成**（一致性模型） | **生成** | **生成** | ✅ **最终资产（与人脸成对）** |
| 按需 | `FABRIC_DETAIL_X` | 材质被画错才补 1 张 | 同左 | 同左 | ⚠️ 一般不用 |

**每人生成张数**：`M0` = 3–4 张（面部 + 服装 + 定妆照 + 拼板），`M1` = 2–3 张，`M2` = 1 张（只出拼板）+ 2 张裁切。**三种模式的最终人物资产都只交 1 张**；视频层另按出镜角色成对加挂 `FACE_CLOSE_X`（1 人 2 张、3 人 6 张）。

> 为什么 `M0` 建议先出 `ROLE_STILL_X`：只有一张脸和一张分离的服装图时，模型拼三视图容易把脸和衣服各挑一个版本，串脸率明显上升。定妆照把两者锁进同一张全身图，再以它为唯一依据做拼板——这正是有经验的用户自己会做的一步，把它写成零素材默认动作。

### 2.1 顺序不可跳步

```
[M0/M1] ROLE_CHARTER_X（文字）
   → CHARACTER_MOOD_X（可选基调）
   → FACE_CLOSE_X + OUTFIT_X（生成 / 裁切）
   → ROLE_STILL_X（生成，建议）
   → ROLE_SHEET_X（一致性模型，唯一最终人物资产）
   → [视频层] 每位出镜角色成对上传 ROLE_SHEET_X + FACE_CLOSE_X
   → FABRIC_DETAIL_X（按需）
[M2] 裁切 FACE_CLOSE_X + OUTFIT_X
   → [可选] ROLE_STILL_X
   → ROLE_SHEET_X
   → FABRIC_DETAIL_X（按需）
```

`ROLE_SHEET_X` 一旦锁定，后续不再回头改 `FACE_CLOSE_X` / `OUTFIT_X`；要改就整条链重出，不补单张。

## 3. 零素材的角色设定 `ROLE_CHARTER_X`（M0/M1 必写）

没有任何图时，**文字就是唯一的身份锚**。S0 的「美学设定 · 人物」子表必须逐位角色写全下面 12 项，S3 每条生成提示词**逐字复制**同一份描述串，不得在同批图里改词。

| # | 字段 | 落到什么粒度 |
|---|---|---|
| 1 | 身份与年龄区间 | 可判断妆造与体态的句子，不写情绪词 |
| 2 | 脸型骨相 | 脸型类型、颧骨 / 下颌 / 眉骨的具体描述 |
| 3 | 眉眼鼻唇 | 形状、间距、厚薄，不用「好看 / 精致」 |
| 4 | 发际线 · 发型 · 发饰 | 含**背面**结构（发髻编法、发饰背面固定方式） |
| 5 | 妆造 | 时代相符的清淡妆；明确禁现代浓妆 |
| 6 | 体型与 `body_ratio` | 写实 7.5–8 / 古装风格化 8.5–9 头身，逐字锁定 |
| 7 | 服装六维 | 形制 / 层次 / 材质 / 固有色与色场接口 / 配饰呼应 / 不对称与生活痕迹（见 `costume-design.md`） |
| 8 | 四朝向结构清单 | 正 / 左 90° / 右 90° / 背 180° 各一行，背面不空白、左右不换边 |
| 9 | 三处记忆点 | 主识别特征 / 材质对比 / 一处不对称细节 |
| 10 | 差异化清单 ≥3 条 | 多角色之间 ≥2 项不同，防串脸与撞脸 |
| 11 | 一处生活痕迹 | 鬓角碎发 / 袖口压皱 / 织物磨边 |
| 12 | 固有色 HEX + 不对称在哪一侧 | 只写固有色，不写主色占比；写明左袖 / 右襟等，防换边 |

**零素材三禁**：

1. **禁虚构引用**：没上传图就不许写「@参考图 1 / 与图 2 保持一致」；身份只由 `ROLE_CHARTER_X` 与上一环生成结果提供。
2. **禁把第一张随机结果当权威**：`FACE_CLOSE_X` 出 4 张挑 1，锁定后才允许进下一步；`ROLE_SHEET_X` 同样出 2–4 张挑 1。
3. **禁跨图改词**：描述串、`body_ratio`、发饰、固有色 HEX 逐字复制，一次只改一个变量（朝向 / 景别 / 动作）。

## 4. S3 分步：按模式给不同的提示词组

| 模式 | S3 必交付的提示词块 | 验收 |
|---|---|---|
| `M0` | `B-Z1` 面部特写生成 / `B-Z2` 服装图生成 / `B-Z3` 定妆照生成 / `B02` 拼板 / `B03` 按需材质 / `B04` 组件库；可加 `B-Z0` 概念基调 | 角色设定 12 项 + 拼板 8 项 |
| `M1` | 缺哪半给哪半的 `B-Z` 块 + 已有半套的裁切/绑定说明 + `B02` / `B03` / `B04` | 同上，另验「已有图 inherit-nothing-else」 |
| `M2` | `B00` 裁切与绑定说明 + `B01` 可选定妆照 + `B02` / `B03` / `B04` | 拼板 8 项 |

可复制模板见 `assets/character-sheet-prompts.md` §14（零素材起点）；项目侧按 `staged-delivery.md` 的「成果二分」规范，全部提示词只进 `提示词全集.md` 的 B 段，注意点只进 `注意点全集.md`。

### 4.1 模型分工按模式调整（三段接力的泛化）

| 模式 | 定基调（Midjourney 类） | 出人物（Seedream 类） | 锁一致（Nano Banana 类） |
|---|---|---|---|
| `M0` | `VISUAL_MASTER_01` + `CHARACTER_MOOD_X`（脸型气质、妆造、面料与配色方向）+ 场景基调版 | `FACE_CLOSE_X` / `OUTFIT_X` / `ROLE_STILL_X` | `ROLE_SHEET_X` / 场景正反打 / `STANDARD_FRAME_01` |
| `M1` | 只补缺的那一半的概念基调，不重画用户已有的那一半 | 缺的那一半 + `ROLE_STILL_X` | 同上 |
| `M2` | **不做人物**，只做视觉母版与场景基调 | 可选 `ROLE_STILL_X` | 同上 |

三条边界不变（v4.1 修订）：基调模型原图**不直接进视频上传序列**；A08 按归纳 meta 指令对参考素材实际归纳 + 分组检查，交付 12 个 HEX 写死的**成品出图提示词**纯文字出图，生成的色卡**两处使用：A 段场景图取色彩方案 + C 段【参考绑定】上传**，A 段场景图同传色卡取色彩方案；A00 母版 / 标准首帧 / 人物资产不挂色卡，全阶段不写 `--sref`，**占比由色场方案与摄影母版写死、不从色卡取**；`ROLE_SHEET_X` 由一致性模型出，是唯一最终人物资产。用户只给一个图像模型时，按同样顺序由该模型全包，不拆分工。

### 4.2 视频层（S5）与输入模式无关

**v3.8 口径**：每条生成条按**六块结构**【视频基本参数】【参考绑定】【摄影母版】【禁止项】【画面描述】【收束与音频】整段交付，模板见 `prompt-examples-video.md` §8。

| 项 | 规则 |
|---|---|
| 人物参考 | **只有两类成对**：`@ROLE_SHEET_X` 四视图资产 + `@FACE_CLOSE_X` 人脸特写。每位出镜角色 2 张；三人同框 6 张、无人物镜 0 张。`FACE_CLOSE_X` 是**唯一允许进视频的过程件**。**v5.1**：后景焦外的不具名背景人影不占参考位，张数仍只按出镜主角算 |
| 不上传 | 四宫格、定妆基准、四格板、单独三视图、服装放大图、`CHARACTER_MOOD_X`、`OUTFIT_X`、`ROLE_STILL_X`、视觉母版、场景基调版 |
| 按需 | `FABRIC_DETAIL_X` 仅在材质被画错时补 1 张；参考位不足时优先保 `ROLE_SHEET_X`，人脸特写优先给近景多的生成条 |
| 色卡 | `COLOR_CARD_01` **两处使用**：A 段场景基调图 / 可选反打同传只取色彩方案 + C 段【参考绑定】上传；A00 母版 / 标准首帧 / 人物资产不挂，全阶段不写 `--sref` |
| 摄影母版 | `PHOTO_MASTER_01` 是文字块，逐字复用、不生成图、不上传 |

**不因为 `M0` 生成过程多出几张图，就往视频里多挂参考**——除 `FACE_CLOSE_X` 外，过程资产一律不上传。

## 5. 状态与下游字段

`stage_state.json` / `generation_plan.json` 必须带：

```json
{
  "input_mode": "zero",
  "input_mode_detail": {
    "M0": ["角色A", "角色B", "角色C"],
    "M1": {},
    "M2": {}
  },
  "asset_policy": {
    "final_character_assets": ["ROLE_SHEET_A", "ROLE_SHEET_B", "ROLE_SHEET_C"],
    "video_character_references": ["ROLE_SHEET_X 上下分区定妆板资产", "FACE_CLOSE_X 人脸特写"],
    "process_assets_never_upload": ["CHARACTER_MOOD_X", "OUTFIT_X", "ROLE_STILL_X"],
    "fabric_detail": "on_demand_only"
  },
  "color_card_usage": "scene_color_scheme_plus_video_reference_binding",
  "scene_image_model": "gpt-image-2.5",
  "scene_prompt_format": "one_shared_body_plus_N_scene_sentences",
  "standard_frame_reference_count": 2,
  "video_prompt_structure": ["视频基本参数", "参考绑定", "摄影母版", "禁止项", "画面描述", "收束与音频"]
}
```

`input_mode` 变更属于 **S0 可改项**；改动时回退到 S0 重出总揽，并同步 S1 分工表与 S3 提示词组，不删除已生成的任何用户文件。

## 6. 验收（进 S4 前）

- [ ] `input_mode` 已判定并写进 `master_overview.md` / `stage_state.json`，不因「没图」卡阶段。
- [ ] `M0`/`M1` 的 `ROLE_CHARTER_X` 12 项写全，描述串在每条生成提示词逐字一致。
- [ ] 前两格来源正确：该裁的裁、该生成的生成，没有虚构参考图，也没有把用户已有图重画一遍。
- [ ] `ROLE_SHEET_X` 每位角色 1 张、四格齐全，过拼板 8 项；`ROLE_STILL_X` / `OUTFIT_X` / `CHARACTER_MOOD_X` 未出现在上传序列，`FACE_CLOSE_X` 仅作视频成对参考出现。
- [ ] `STANDARD_FRAME_01` 只挂 **2 张**参考（主角拼板 + 场景反打（可选），**不带色卡**），与输入模式无关。
- [ ] 色卡为 12 色归纳产物，且**只**在 C 段【参考绑定】出现；A 段场景基调图 / 可选反打有 `@COLOR_CARD_01` 取色彩方案；A00 母版 / 首帧 / B 段人物资产无 `--sref`。
- [ ] 视频提示词六块齐全，【摄影母版】逐字一致且未被当作图片上传。
- [ ] 三条铁律、色场方案、逐镜时间码未被输入模式改动。

## 7. 常见误用

| 误用 | 后果 | 正确做法 |
|---|---|---|
| 把「从已有资产裁切」写成通用步骤 | 零素材用户拿到一堆无法执行的裁切说明，链断在第一步 | 先判 `input_mode`，M0 必须给生成提示词 |
| 因为用户没图就反复追问、停在 S0 | 违反「缺项按默认假设、不阻塞」 | 默认 `M0`，直接继续 |
| 零素材时把文字描述写得很虚（「清秀古装少女」） | 每张图各画一张脸，串脸 | 12 项 `ROLE_CHARTER_X` 落到骨相 / 发饰背面 / HEX / 不对称侧 |
| 把 `M0` 多生成的过程图也挂进视频 | 同信息重复输入，模型在几张略不同的脸之间挑错 | 只挂 `ROLE_SHEET_X` + `FACE_CLOSE_X` 两类成对，其余过程图一张不挂 |
| 用 `--sref` 把整张色卡当风格垫图挂到场景基调图上 | 六个场景出现色块方格与 HEX 小字、颜色长一样 | 改用平台参考图槽位 + 正文「只取色彩方案」限定句；仍不写 `--sref` |
