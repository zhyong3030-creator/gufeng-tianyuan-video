# 模型适配层：图像 + 视频双层，时长上限驱动整体规划

> **v4.3 当前默认口径**：A08 色卡是**成品出图提示词**——先用「12 色归纳 meta 指令」对参考素材做实际归纳 + 分组检查，再把 12 个 HEX 写死成纯文字出图提示词、不传参考图，且**必须先于 A01 完成**。色卡**两处使用**：`A01–A0N` 场景基调图与可选反打**同传 `@COLOR_CARD_01`、只取色彩方案**（12 色色值 / 主辅色结构 / 五级明度，不取色块的版式、HEX 标注文字与构图），`C` 段【参考绑定】照旧上传；`A00` 母版、`A09` 标准首帧（恒 2 参考）与 B 段人物资产仍不挂色卡，全阶段不写 `--sref`。场景图推荐 `gpt-image-2.5` 类指令式图像模型，通用正文含固定画质段且逐字一致。`A01–A0N` 为「一条通用正文 + N 条场景句」；`SCENE_REVERSE_0X` 反打**可选**；提示词纯净原则不变（「参考图怎么用」允许进代码块）。v4.3 起摄影母版为一段连续专业摄影描述（只写跨镜头统一项、不含具体焦段），焦段与 T 光圈下放到【画面描述】的【镜头N | 时间码 | 镜头名】逐镜块；【画面描述】= 全局设定段 + 逐镜块，占比 / 光位 / 肤色 / 质感 / 人物锁定各只出现一次。规则见 `color-system.md` §7 / §7.8、`SKILL.md` 第 15 / 20–24 条与 `prompt-examples-video.md` §8。

> **v3.3 角色参考包变更**：第一张图必须是 `FACE_QUAD_01` 面部特写四宫格（同一图四等分：正 / 左 90° / 右 90° / 背 180°，全为头部特写），后面每张定妆图按 `character-sheet-spec.md` §4.4 对应性矩阵指回它；全包统一纯色暖灰 `#C6BCB1` + 三点式 5500K 中性光 + 105mm（头）/85mm+（身）+ 低密度 Tiffen 黑柔 + 无现代浓妆；另产朝向三视图、四格定妆板与六张单图，定妆包验收 13 项。出图前先过 `character-design-aesthetics.md` 设计自检 6 问与 `costume-design.md` 服装自检 6 问。本文件涉及角色参考包的具体表述以 `character-sheet-spec.md` 为准。

**原则：六段式内容不变，形态随模型变；成片镜头不变，生成条随模型上限变。**
色场规律、光位、圆形锚点、肤色与三层结构是铁律，任何模型都不改；改的是语言、参考图绑定、负向词机制、时间码结构、每镜秒数、**生成条数**与交付物清单。

能力数据库：`assets/model_profiles.json`（检索 2026-11-05，含来源链接）。改能力只改 JSON，不改脚本。完整实例见 `references/prompt-examples-image.md` 与 `prompt-examples-video.md`；用户操作见 `references/usage-guide.md`。

## 1. 两层模型，各自影响什么

| 层 | 影响提示词 | 影响产出结果 | 必查能力 |
|---|---|---|---|
| **图像层**（定妆/三视图/四格板/单图/定景/色卡/标准首帧/故事板） | 语言、结构化程度、参数行、负向词机制、参考图编号写法；**定妆阶段不套六段式色场** | 参考图包规模（基准图 + 三视图 + 四格板 + 六张单图）、`body_ratio`、光照模式、标准首帧策略、是否需要 LoRA | 最大参考图数、是否有负向字段、是否支持对话式改图、分辨率与画幅 |
| **视频层**（动态） | 时间码 beat、动作裁剪、运镜写法、音频约束、负向词机制 | **镜数、每镜秒数、生成条数、每条装几个镜头**、分镜表列 | **单次最短/最长 + 档位**、多模态参考上限、首尾帧、返回末帧、局部重绘、原生音频 |

换任一层模型都回退到 **S1** 重跑选型与适配，不沿用旧模型的提示词形态与规划。

## 2. 单次时长上限 → 整体分镜规划（本版核心）

### 2.1 两个长度必须分清

| 概念 | 定义 | 随模型变？ |
|---|---|---|
| **editorial shot 成片镜头** | 最终剪辑里的镜头，时长按用户在 S0 给定的区间（建议 **2–4 秒，可改**） | 否 |
| **generation unit 生成条** | 一次提交给模型的生成，必须是允许档位且 ≤ `max_duration_s` | **是** |

**上限 ≠ 建议。** 30s 上限的价值是把相邻短镜头合成一次生成、用时间码显式声明切镜，减少跨生成换脸与跳色；剪辑时仍按用户给定区间（建议 2–4 秒，可改）切回短镜头节奏。

### 2.2 已核实的硬约束（以平台当日为准）

| 模型 | 最短–最长 | 档位 | 示例：35 秒成片的生成条数（按 `T` 重算） | 规划后果 |
|---|---|---|---|---|
| Seedance 2.0 | 4–**15s** | 4/5/10/15 | 3（15+15+5） | 一条覆盖约两个段落；豆包 App 常锁 5/10s，需网页端才有 15s |
| Seedance 2.5 | 4–**30s** | 4–30 滑杆 | 2（30+5） | 一条几乎装全片；必须写 12 段时间码 + 显式切镜；可用返回末帧续接与局部重绘 |
| Kling 3.0 | 3–**15s** | 5/10/15 | 3 | 15s 内约 6 个 labeled shots；负向框只写稳定性瑕疵 |
| Veo 3.1 | 4–**8s** | 4/6/8 | 5（8×4+4） | 生成次数最多；每条 8s 排 3–4 个 beat；跨条一致性最脆弱 |
| Runway Gen-4.5 | **5/10s** | 5/10 | 4 | 不支持负向词，只写正向画面 |
| Wan 3.0 | 2–**30s** | 2/5/10/15/30 | 2 | 低成本长草稿，验证节奏后再交主力精修 |
| 海螺 2.3 | ~6–**10s** | 6/10 | 6 | 1080p 与 10s 互斥；只出近景 |
| Sora 2 Pro | 4–20/25s | — | 不规划 | **deprecated**：Web/App 2026-04-26 停服、API 2026-09-24 终止 |

### 2.3 脚本计算顺序

1. **总时长 `T`、镜数、段落数由用户在 S0 给定**（未给才用建议值 35 秒 / 13–16 镜 / 5 段并标注「可改」）；`每镜秒数 = T / 镜数`。`--duration` 传 `T`，不传 35。
2. 每镜秒数 > `suggested_shot_s` → 加镜；> `max_duration_s` → 拆镜或换模型（WARN）。
3. 生成条取**不超过上限的最大可用档位**，逐条量化到允许档位；末条不足 `min_duration_s` 时补到最短并提示剪辑裁掉。
4. 按镜头中点把 shots 分进生成条，输出 `timecoded_beats`；每个 beat 只一个可见动作、切镜显式。
5. 输出 WARN：前端档位限制、`verify`/`deprecated` 状态、末条裁剪。

`generation_plan.json` 里的 `units[].shot_ids` 与 `units[].beats` 直接决定 S4 分镜表的「生成条 ID」列与 S5 的时间码提示词。

## 3. 十三条改写规则

1. **语言**：中文优先模型直出中文六段；英文优先逐段译，六段顺序与信息量不变，不压成风格词。
2. **参考图绑定**：多图模型给每张**稳定编号**，分别写「继承什么 / 不继承什么 / 其余一律不继承」；单图模型改用标准首帧 + 角色外观写进正文；纯文本模型全自包含 + 固定描述串逐字复制。角色参考绑定必须写「纯暖灰背景与三点式棚拍还原光一律不继承，不继承任何光位与光比」，并逐项写明 `@ROLE_BOARD_01` 上方两格只给面部细节、左下格只给服装材质、右下格只给背面外观，见 `character-sheet-spec.md` 第 14 节。
3. **图像层形态**：Nano Banana 对话式白话 + 正向约束句（无负向字段）；GPT Image 2 / Seedream 用分段或 JSON 字段（`[变量]` 占位）；Midjourney 压成关键词串 + 参数行（版本需现场确认）；FLUX/SDXL 用长句或 tag + 独立负向词与参数文件。**`--stage character` 例外**：所有模型都改按 `character-sheet-spec.md` 的影棚定妆图 + 朝向三视图 + 四格定妆板 + 六张单图模板写，锁定 `body_ratio` 与三点式 5500K 中性白棚光；去掉色卡引用 / `--sref` / 主色占比 / 成片主光段 / 景深层，额外产出 `character_prompts.md`（六条实例）、`negative_character.txt` 与 `character_sheet_checklist.md`（10 项）。
4. **动作裁剪**：动作时长 ≤ 单镜时长的 70%；超出的拆成两镜，不拉长单镜。
5. **时间码**：长生成条必须按 2–4 秒切 beat，每 beat 一个动作 + 切镜声明；`Kling` 用 `Shot 1…Shot N` 标注，其余用 `0–3s / 3–6s`。
6. **运镜**：有原生控制时单独写 CAMERA 段；否则写进自然语言并禁掉环绕、甩镜、变焦。
7. **音频**：带原生音频必须写「无对白、无口播、无字幕朗读，仅环境声」。
8. **色场（v4.1）**：A08 交付的是**把 12 个 HEX 写死的成品出图提示词**（纯文字出图、不传参考图；归纳 meta 指令只作方法），生成的色卡**两处使用：A 段场景图取色彩方案 + C 段【参考绑定】上传**；A 段场景图同传色卡取色彩方案；A00 母版 / 标准首帧 / 人物资产不挂色卡，全阶段不写 `--sref`，占比数值由色场方案表与摄影母版写死、不进场景提示词代码块。
9. **负向词按机制**（写错会反向生效）：Veo 独立字段只写**纯名词**、禁 `no/don't`；Kling/Wan 只写具体稳定性瑕疵；Runway **完全不写**，只写应出现的画面；Nano Banana/Seedance 无可靠字段，改正向约束句。
10. **参数**：Midjourney V8 附 `--ar/--seed`（`--cref/--oref` 仅 V6/V7 旧版可用，版本现场确认；**`--sref` 不在场景图参数行**）；开源模型附 seed/CFG/steps；平台型只写画幅与时长，不臆造参数。
11. **画幅**：9:16 时圆形锚点仍居中，前景遮挡降到 10–20%，留白从左右改为上下。
12. **一致性**：多图靠参考编号、单图靠固定描述串 + 每镜重复；任何模型都不得在逐镜提示词里改服装描述。
13. **结尾留白**：最后一段不加新动作、不加特效、不加对白，停在带主色的空气面。

## 4. 中文改写骨架（六段逐段对应，v3.7 起唯一语言版本）

```
[1 主体与动作] <人物固定描述串，逐字复制>，<一个可见动作>。
[2 色场] 主色 <主色> 约 65%，进入服装、建筑、自然、织物、道具、地面、空气与环境光，覆盖 3x3 九分区；辅色 <辅色> 约 20% 落在阴影与远景；暖主光 + 冷环境反射；<浅主色载体> 作为大面积低彩度承载物。
[3 构图] <景别>，人物占画面高度 <比例>；<圆形锚点> 位于下三分之一；<10-30%> 失焦 <前景遮挡物>；<带主色的空气面> 留白。
[4 光与质感] 高位斜后侧光（摄影机反方向 120-150 度），发丝与袖缘金色轮廓光，正面弱暖补光；暖象牙肤色；暗部抬高保留纹理；奶油金高光柔化扩散；柔焦、大而软的散景。
[5 镜头] 眼平静态机位，仅极轻微推进；<焦段倾向>；中浅景深；失焦前景—清晰主体—虚化远景三层。
[6 负向/约束] <按模型机制写：纯名词 / 独立字段 / 正向约束句 / 完全不写>
```

> 仅平台参数行、资产 ID、器材型号与单位色值保留原文；不提供英文版。

## 5. GitHub 高星仓库提炼的写法（写进每条提示词）

来源与星标见 `references/model-profiles.md` 第 4 节。核心五条：

1. 不写 `epic / stunning / 电影感 / 高级感`，改写可见物件、光位、比例、真实机身镜头参数与物理反应。
2. 参考图给稳定编号 + inherit-nothing-else 句。
3. 时间码切分：每 beat 一个动作 + 一条声音，切镜显式声明。
4. 负向词按模型机制变（见规则 9）。
5. 结尾留白、不堆特效；Reroll 是正常流程，先按 FAILURE-MODES 诊断再重抽。

## 7. 生成执行 runbook（S6）

1. **小样**：`ROLE_REF_01`（纯色暖灰影棚三点式中性光、全身正面、锁定 `body_ratio`）+ 朝向三视图 `ROLE_TRIVIEW_01` + 四格板 `ROLE_BOARD_01` + 六张单图 + 3 张空镜 + 1 张 成品色卡出图提示词（仅视频用）+ 1 张标准首帧（2 参考、不带色卡） + 1 条短镜头；先过 `character-sheet-spec.md` 定妆包 13 项，再过 `model-selection.md` 成片 6 项。
2. **确认**：小样交用户审阅，明确通过后才能批量。
3. **批量**：按 `generation_plan.json` 的 unit 逐条生成，记录 seed / 档位 / 参考编号 / 挑片理由。
4. **通道**（生成能力由用户选定）：A WorkBuddy 内生成 / B 用户外部平台 / C Flova 项目（按当前专家 Connector 指引交接，本 skill 不自行发起）。
5. **修错顺序**：错帧局部重绘 → 补参考图 → 复用首帧与色卡 → 拆 beat → 负向词 → 最后才换模型。
6. **统一**：所有镜头共用标准首帧、摄影母版与【参考绑定】里那张色卡；成片统一 LUT，不逐镜调色。
7. **验收**：`color_field_audit.py` 量化 + `color-system.md` 人工清单。

## 8. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| S0 就谈模型、倒提示词 | 总揽被工具条件带偏，用户还没确认方向 | 严格 S0 只出总揽 |
| 只适配视频模型、忽略图像模型 | 参考图包与首帧不符合图像模型能力 | 两层都跑 `--image-model` / `--video-model` |
| 把 30s 上限理解成 30 秒长镜头 | 动作崩坏、节奏拖沓 | 时间码拆成 2–4s beat，剪辑切开 |
| 换模型沿用旧规划 | Veo 8s 稿拿去 Seedance 2.5 生成，条数与时间码全错 | 回退 S1 重跑 `model_adapter.py` |
| 换模型沿用同一份提示词 | 单图模型丢参考信息、英文模型读中文失效 | 每次换模型都重跑适配 |
| 负向词机制写反 | Runway 越禁越出现、Veo 反向生效 | 按规则 9 逐模型改写 |
| 只给提示词不给用法 | 用户不知道传哪些图、选几秒、生成几次 | 每阶段附使用步骤，见 `usage-guide.md` |
| 定妆图带场景 / 彩光 / 暖金逆光 / 半身 / 没有三视图与四格板 | 旧背景与同一道光被继承进每个镜头，色场锁死、转身与全身镜换脸、近景五官崩坏 | 按 `character-sheet-spec.md` 重出影棚基准图 + 朝向三视图 + 四格板 + 单图，再谈模型 |
| 未确认就批量 | 成本浪费、方向偏差 | 严格小样 → 确认 → 逐批 |
