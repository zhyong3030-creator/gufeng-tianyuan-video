# 阶段闸门：一步步产出并引导用户执行（v4.0 双通道 · 三后端 / v5.0 七步引导）

> **v5.0 交付口径（优先级高于下文旧版阶段表）**：对用户只讲 `SKILL.md` 的「7 大步小白引导」——0 准备 / 1 视频总规划 / 2 视觉美学基调 / 3 视频分镜设计及脚本 / 4 人物场景资产设计 / 5 视频生成设计 / 6 自查；**每小步弹 A / B / C 选择框**，**每大步只给三件套**（本地一份 md + 对话框直接给提示词与用法 + 每条提示词各一个独立一键复制框）；只给生成类提示词，规划 / 分镜 / 自查步给表格清单、不硬造；旧文档先归档到 `.backup/旧版完整参考包-<日期>/` 再重建。下文的 S0–S7 是**内部引擎**，不出现在交付文件与对话里。`autopilot` 显式授权时跳过引导、不弹框，按本文件 §8 连续产出。

> **v3.6 / v5.2 范围提示**：默认角色资产是每人 1 张 `ROLE_SHEET_X` 上下分区定妆板（出图提示词逐字采用用户 2026-11-08 定稿，版式上 1/3 / 下 2/3，不回退 1:1 四等分）；本文件凡写「面部四宫格 / 六类实例 / 13 项」处，均指用户主动要求的**扩展定妆包**。S0 必须判定 `input_mode`（`M0 零素材` 默认 / `M1 部分` / `M2 已有`），S3 按模式给不同提示词组，见 `references/input-modes.md`。

**`guided`（默认）一次只推进一个阶段。** 用户只给一个主题时，第一份产出必须是**整支片子的影像总揽**，不是 brief、不是模型清单、不是提示词。每个阶段结束必须停下，给出「本阶段产出 / 关键决策点 / 使用指引 / 现在请你做什么 / 收到什么确认后继续」，等用户回应再进下一阶段。**用户显式授权切 `autopilot` 时**按 §8 连续产出并自动放行，S6/S7 交给 `execution_backend` 指定的后端（`libtv` / `workbuddy` / `external`）；默认状态永远是 `guided`。

## 1. 八个阶段（v3 顺序）

| 阶段 | 只产出这一份 | 用户要做的动作 | 确认闸门 |
|---|---|---|---|
| **S0 影像总揽** | `master_overview.md`（结构 / 基调 / 美学设定含角色与服装设计字段 / 色彩氛围 / 光影特点 / 摄影设定 / **输入模式盘点与 `ROLE_CHARTER_X`**） | 只确认总揽是否通过；**不谈模型** | 五段结构、主色方向、角色差异化清单、服装六维、**输入模式判定**都通过 |
| **S1 模型选型** | `model_plan.md`（意向询问 + 主推/备选 + 两层能力表 + 生成通道；多图像模型时含三段分工与接力顺序） | 给意向图像+视频模型，或采用推荐 | 模型与访问方式确认 |
| **S2 适配规格与整体规划** | `adaptation_spec.md` + `generation_plan.json` + `usage_guide.md` | 确认生成条时长不超上限、规划与五段结构一致 | 适配规格通过 |
| **S3 角色资产（默认每人 1 张 `ROLE_SHEET_X`；按输入模式给 `M0` 从零生成组 / `M2` 裁切说明）+ 定景提示词 + 用法** | `character_prompts.md`（按模式选 `B-Z` 生成组或裁切说明 + 拼板 + 角色/服装设计段）+ `prompts_character_scene.md`（色卡 / 空镜 / 标准首帧）+ `character_sheet_checklist.md`（拼板 8 项；扩展包 13 项）+ 上传/参数/挑图步骤 | `M0` 先按 12 项文字设定出面部 / 服装 / 定妆照，再出拼板；`M2` 裁两格后直接出拼板，回传小样 | **设计自检 6 问 + 服装自检 6 问 + 拼板 8 项 + 成片 6 项**都通过（扩展包另过 13 项） |
| **S4 脚本与分镜** | `shot_list.csv`（含生成条 ID、模型单次上限） | 确认节奏、镜序、每条装了哪几个镜头 | 分镜通过 |
| **S5 逐镜提示词 + 用法** | `prompts_shots.md` + 粘贴/档位/挑片/修错步骤 | 抽查 2–3 条提示词与用法 | 提示词通过 |
| **S6 生成执行** | 每批 ≤5 镜的镜头素材 | 按步骤跑完这一批并回传 | 逐批闸门 |
| **S7 验收交付** | 统一调色成片 + `audit_report.json/md` | 剪辑、统一 LUT、跑验收脚本 | 完成或回退 |

## 2. 每阶段结尾的固定引导块

阶段产出后，必须原样输出这个结构（内容按阶段替换）：

```
✅ 本阶段产出：<具体文件名 / 表格>
   关键决策点：<本阶段唯一需要拍板的事>。
   使用指引：<拿到这份东西之后具体怎么做，1-2 句>

👉 现在请你：<一个具体动作，不要给多个并列任务>
   A. 通过，继续下一步
   B. 修改 <本阶段可改的具体项，列出 2–3 个>
   C. 换方向 <本阶段可换的选项>

⏸ 收到你的确认后才会进入 <下一阶段名称>；在此之前不会生成后续内容。
```

引导规则：

- 「现在请你」只给**一个**动作；S3 是「跑小样并回传」，S6 是「跑完这一批并回传」。
- **「使用指引」不能省**，也不能写成「详见文档」；要写出本阶段真正要做的第一步（例如 S3：先过角色设计 6 问与服装造型 6 问、定 `body_ratio` 与 `face_spec` 模式、确认面部/服装参考槽位，**第一张图只出 `FACE_QUAD_01` 面部四宫格并锁定**，再以它为唯一面部依据出 `ROLE_REF_01`、朝向三视图、四格板与六张单图，最后才出色卡 / 空镜 / 标准首帧）。完整步骤见 `references/usage-guide.md`，回复里给精简版。
- 选项 B 必须列出本阶段真正可改的项（S0 改主色/五段时间/圆形锚点；S1 换模型；S2 改镜数/时长；S4 改镜序），不写「其他建议」。
- 明确写出暂停边界，避免用户以为后面已经做完。
- 不把下一阶段的产物提前贴出来「供参考」。

## 3. S0 与 S1 的专门约束

**S0**
- 输入只有主题（可补时长/画幅）；缺项按 `assets/overview-template.md` 默认值假设并在文末标注，不反复追问。
- **禁止出现**：模型名、平台名、提示词、分镜表、参数行、负向词。
- **必做输入盘点**（v3.6）：扫 `assets/` 判定 `M0 零素材`（默认）/ `M1 部分素材` / `M2 已有资产`，写进 `master_overview.md` 与 `stage_state.json`；顺带问一句有没有人物图，**不回答就按 `M0` 继续，不追问、不卡阶段**。`M0`/`M1` 同时定稿 12 项 `ROLE_CHARTER_X` 文字设定（见 `input-modes.md` §3）。这属于美学与工作量判断，不算模型名或提示词。
- 每一项必须落到可见物件、光位、比例或数值；不写抽象风格词。
- 结尾引导块只能问「总揽是否通过」。

**S1**
- 必须先**主动提问**：「你打算用哪个图像模型、哪个视频模型？可用平台/预算/是否要本地部署？」
- 同时给出：主推组合 + 备选 1–2 个 + 理由 + 两层硬约束表（单次时长与档位、参考图上限、负向词机制、音频、语言、状态）+ 对规划的初步影响。
- `deprecated` 模型不进推荐；`verify` 模型标注先跑小样。
- 即使用户最初就指定了模型，也要给推荐并请其确认，不自己拍板。
- 用户选 B「用我的意向模型」时，若档案没有该模型，先按 `model-profiles.md` 说明能力未知、需现场确认，再按通用适配规则继续；不臆造参数。
- 用户给了 **≥2 个图像模型**时，按 `model-selection.md` 4.1 给「定基调 / 出人物 / 锁一致性」资产分工总表、接力顺序、三处冲突解法与视频上传出口（人物只走 `ROLE_SHEET_X` + `FACE_CLOSE_X` 两类）；用户只给一个模型时不拆。分工调整属于 S1 可改项，改完要同步 `stage_state.json` 的 `image_model`。

## 4. 用户指令映射

| 用户说 | 动作 |
|---|---|
| 「通过」「继续」「下一步」「OK」 | 记录当前阶段确认，推进到下一阶段，只产出该阶段内容 |
| 「改主色 / 换配色 / 换美学设定」 | 回退到 **S0**，重出总揽；模型选择保留但需重新确认 |
| 「换模型」「我用可灵 + 即梦」 | 回退到 **S1**，重跑选型与 S2 整体规划（镜数/生成条/提示词形态全重算） |
| 「小样不对 / 脸变了」 | 停在 **S3**，按修正顺序改参考图 → 提示词 → 最后模型 |
| 「镜头太长 / 节奏拖」 | 回退到 **S2**（时长规划）或 **S4**（镜序） |
| 「全部做完」「一次性出」 | 允许连续产出 S0–S5 的**文档**，但 S6 生成与导出仍逐批确认（未指定平台，**不切 autopilot**） |
| 「交给 libtv 全自动」「不用问我，直接出成片」 | 切 `autopilot`：设 `run_mode=autopilot` → 连续产出 S0–S5 并自动门禁留痕 → `build_handoff.py` 打包 → 整体委托 libtv Agent 跑完 S6/S7 → 回读验收。见 §8 |
| 「先别生成」 | 停在 S5，只交文档 + 用法 |
| 「不知道怎么做」 | 只补当前阶段的操作步骤，不推进阶段 |
| 「我没有任何人物参考图」 | 确认 `input_mode=zero`（本来就是默认），S3 走 `M0` 从零生成组；**不回退、不追问、不减规格** |
| 「我补几张人物图 / 只补了服装图」 | 回退到 **S0** 改判 `M2` 或 `M1`，同步 S1 分工表与 S3 提示词组；不重排分镜、不删已有文件 |

## 5. 状态管理

用 `scripts/stage_state.py` 记录进度，默认项目目录 `<工作区>/deliverables/color-field-<主题>/`：

```bash
python3 scripts/stage_state.py --project <目录> init --theme "雪夜药铺" --input-mode zero --run-mode guided
python3 scripts/stage_state.py --project <目录> init --theme "雪夜药铺" --run-mode autopilot   # 仅用户显式授权后
python3 scripts/stage_state.py --project <目录> next          # 打印当前阶段与引导块
python3 scripts/stage_state.py --project <目录> advance --note "总揽通过"
python3 scripts/stage_state.py --project <目录> set --video-model seedance-2.5 --image-model nano-banana-2 --channel B
python3 scripts/stage_state.py --project <目录> rollback --stage S1 --note "换模型"
python3 scripts/stage_state.py --project <目录> status
```

- `next` 只读状态不改文件；`advance` 才写入确认记录。
- 状态里分别记录 `image_model` / `video_model` / `channel`，S1 确认后写入。
- 回退清除该阶段之后的确认记录，保留之前产物，不删除任何用户文件。
- 跨会话续做先运行 `status`，从记录阶段继续；`status` 同时显示 `run_mode`。
- `autopilot` 下 `advance` 的 note 必须记为「自动门禁通过」，不得伪造用户确认；每条放行写 `autopilot_log`。

## 6. 阶段专用约束

- **S2**：必须运行 `model_adapter.py`，`generation_plan.json` 的每条生成时长 ≤ 模型 `max_duration_s` 且落在允许档位；WARN 未处理不进 S3。
- **S3（默认精简规格，v3.6，适用于全部输入模式）**：只给提示词 + 用法，不声称已生成图片；用户回传小样后才做检查。**先读 `input-modes.md` 判定的 `input_mode`**：`M0 零素材`（默认）给 `B-Z1` 面部 / `B-Z2` 服装 / `B-Z3` 定妆照的**从零生成提示词** + 12 项 `ROLE_CHARTER_X` 文字设定；`M1` 缺哪半补哪半、已有半套写 `inherit-nothing-else`；`M2` 给裁切与绑定说明。三种模式都以 `B02` 出**每人 1 张 `ROLE_SHEET_X` 上下分区定妆板**为唯一最终人物资产，过拼板 8 项；v3.8 视频层另按出镜角色成对加挂 `FACE_CLOSE_X`（唯一允许进视频的过程件），其余过程资产（`CHARACTER_MOOD` / `OUTFIT` / `ROLE_STILL`）一张不上传；`STANDARD_FRAME_01` 只挂 **2 张**参考（主角拼板 + 场景一致性版，不带色卡），色卡第一处在 A 段场景图取色彩方案、第二处在 C 段【参考绑定】。模板 `character-sheet-prompts.md` §14，验收 `character_sheet_checklist.md`（拼板 8 项）。
- **S3（扩展定妆包，仅用户主动要求完整多视图时启用）**：硬规则：**第一张必须是 `FACE_QUAD_01` 面部特写四宫格**（同一图四等分 2×2：左上正面 0° / 右上左侧 90° / 左下右侧 90° / 右下背面 180° 头部背面，四格全为头部特写、同一人同一妆造同一尺度），出 4 张挑 1 后锁定为唯一面部身份锚。全包统一**纯色暖灰 `#C6BCB1` 无缝影棚 + 三点式 5500K 中性白还原光 + 105mm（头）/85mm+（身）+ Tiffen Black Pro-Mist 1/8 低密度黑柔（仅高光轻晕，不是柔焦 / 景深 / 雾感）+ 清淡妆造无现代浓妆 + 全清晰 + 真实皮肤与材质质感**；定妆基准 `ROLE_REF_01` 为全身正面、头到鞋完整、锁定 `body_ratio`。另外必产正 / 正侧 90° / 背 180° 朝向三视图 `ROLE_TRIVIEW_01`、上 1/3 两张头部特写 + 下 2/3 放大服装与背面全身的四格板 `ROLE_BOARD_01`，以及六张拆出的单图。**后面每张图都写明引用 `FACE_QUAD_01` 哪一格并按 §4.4 对应性矩阵逐项一致**；服装按 `costume-design.md` 六维与四朝向清单写全。色场占比、成片暖逆光与金色轮廓光、前景遮挡、景深只进 `STANDARD_FRAME_01` 与场景空镜；色卡 / 空镜 / 首帧不带影棚黑柔。不得把带成片光影的半身画面标为定妆图，不得把「正面/四分之三/全身」当三视图，也不得把三个「多视图」互相替代。裁头放大格失败按 `character-sheet-spec.md` §9.3 降级；光位继承 / 整屏雾感 / 暖灰染色则整套降级平光 + 无滤镜或整套切 `layered`。出图前先过 `character-design-aesthetics.md` 设计自检 6 问与 `costume-design.md` 服装自检 6 问。规范 `character-sheet-spec.md`，模板 `character-sheet-prompts.md`，验收用 `character_sheet_checklist.md`（13 项）。
- **S4**：分镜表必须含「生成条 ID」与「模型单次上限」列；一条生成条里用时间码拆成用户给定区间的镜头（建议 2–4 秒，可改）；总时长 `T`、镜数、场景数与段落数均为 S0 项目参数，不卡死。
- **S5**：每条提示词按所选视频模型的负向词机制与语言写；附「粘到哪里 / 传哪些参考 / 选几秒 / 生成几次 / 怎么挑片 / 怎么修错帧」。
- **S6**：`guided` 下每批 ≤5 镜、未确认不扩大批次、不自动调用产生费用的生成能力；通道 C 按当前专家 Connector 指引交接。**`autopilot` 下**由 libtv Agent 按 manifest 数量上限一次跑完，本 skill 自身仍不直接发起生成，只打包、留痕与回读验收（§8）。
- **S7**：`color_field_audit.py` 只测成片段，用 `--start/--end` 排除讲解与 UI；报告区分「实测数值」与「人工检查结论」。

## 7. 禁止事项

- 不在一个回复里同时交付 S1–S5 的全部文档（用户明确说「全部做完」时除外）。
- 不把「引导块」省略，也不把它写成一句「有需要告诉我」。
- **不省略「使用指引」**，不只丢提示词。
- 不在用户未确认小样前批量生成镜头。
- 不把 WorkBuddy 自行编写的提示词、分镜说成 Flova 或某平台已完成的产物。
- `guided` 下不因用户沉默就默认通过、等待明确回应；`autopilot` 的预授权必须由用户显式说出，沉默不算（§8）。


## 8. 双运行通道与自动门禁（v4.0 · 两通道都跑到 S7）

> 本章只改「**谁来放行闸门**」与「**谁跑 S6/S7**」，不改任何阶段产出、固定风格、色场规则、提示词口径与验收标准。`guided` 是默认且唯一默认值；`autopilot` 必须用户显式授权。**v4.0 起 autopilot 与 libtv 解耦**：`execution_backend` 三选一（`libtv` / `workbuddy` / `external`），libtv 未连接时换后端即可，两条通道都能跑到 S7。细则见 `agent-autopilot.md` 与 `SKILL.md` 第 19 条，离线自检 `scripts/verify_channels.py`。

### 8.1 两条通道对照

| 项 | `guided` 逐步引导（默认） | `autopilot` Agent 托管（显式授权） |
|---|---|---|
| 服务对象 | 人：自己看懂、自己动手、逐阶段确认 | 执行后端：按整包一次跑到成片 |
| 阶段推进 | 每阶段一停，等「通过 / 继续」才 `advance` | S0–S5 连续产出，**规则校验通过即留痕放行** |
| 引导块 | 必给：产出 / 决策点 / 使用指引 / 唯一动作 / A·B·C / 暂停边界 | 不输出「请你确认」，改为写 `autopilot_log` 门禁记录 |
| S1 模型 | 主动问意向 + 给推荐 + 等选择 | 直接用生产包定稿组合（或能力档案主推组合），写进 manifest |
| S6 生成 | 每批 ≤5 镜、逐批确认、生成 2–3 挑 1 | 整包交给 `execution_backend`，按 manifest 的生成条数与挑片次数一次跑完 |
| S7 导出 | 用户剪辑 + 统一 LUT + 跑验收脚本 | 选定后端拼接 / 统一 LUT / 导出；**回读状态与产物后才算完成** |
| 执行后端 | 用户自己的平台 | `libtv`（优先）/ `workbuddy` / `external`；libtv 不可用换后端，不回退 `guided` |
| 产物归属 | 用户平台产物 | 按后端写「libtv Agent / WorkBuddy / 用户平台生成」，不冒充本 skill 产出 |

### 8.2 授权语句与不授权

| 用户说 | 判定 |
|---|---|
| 「一步步来」「先出总揽」「确认通过」「继续」 | `guided`，正常闸门 |
| 只给主题、沉默、「先看看」「只交文档」 | `guided`，**不推断为预授权** |
| 「交给 libtv 全自动」「不用问我，直接出成片」「一次做完」 | `autopilot` → 启用（不再要求点名平台；未点名默认 `libtv`，不可用按 §8 降级换后端） |
| 「全部做完」「一次性出」（未提平台） | **仍是 `guided`**：仅允许连续产出 S0–S5 文档，S6 仍逐批确认 |

### 8.3 自动门禁（替代用户确认，但必须留痕）

| 阶段 | 自动放行条件 | 不过怎么办 |
|---|---|---|
| S0 | `master_overview.md` 五段结构 / 输入模式 / 12 项 `ROLE_CHARTER_X`（M0）/ 色场占比 / 光影摄影两节齐全 | 停下补文档，不进 S1 |
| S1 | 生产包有定稿的图像 + 视频模型，或能力档案里有 `active` 主推组合 | 停下并列出可选组合，不臆造模型 |
| S2 | `generation_plan.json` 每条生成时长 ≤ 模型上限、无未处理 WARN | 停下重算规划 |
| S3 | 六块结构模板（含逐镜块）、A08 成品色卡出图提示词（12 HEX 写死）、A01–A0N 通用正文 + 场景句、可选统一反打、A10 一段式摄影母版（不含焦段）齐全；人物两类成对 | 停下补齐 |
| S4 | `shot_list.csv` 含生成条 ID / 模型上限 / 时间码 beat，总时长对得上 | 停下重排 |
| S5 | 每条提示词六块齐全、摄影母版逐字一致、色卡在【参考绑定】为第二处使用、无英文整句 | 停下修提示词 |
| S6 / S7 | 由 `execution_backend` 执行；本 skill 只校验 manifest 数量上限、回读产物与导出成片 | 后端执行失败即停、汇报、回退 `guided`；**换后端不算失败** |

每次自动放行写 `autopilot_log`：阶段、时间、校验项、结果、依据文件；`stage_state.py advance --note "自动门禁通过"` **不得写成「用户确认通过」**。

### 8.4 数量与成本上限（manifest 必填）

`generation_units`（生成条数）、`picks_per_unit`（每条挑片次数，默认 2–3）、`max_total_generations`（= 条数 × 挑片次数）、`max_retries_per_unit`（默认 1）、`stop_on_limit`（true）。超出即停并汇报，**不得静默重跑或扩大批次**。幂等键按「项目 + 生成条 ID」稳定生成，重发同一键只恢复原运行、不产生新任务。

### 8.5 交付与回退

- 交接包 = `libtv_handoff.md`（给后端的自然语言指令 + 五条硬约束 + 按后端的跑法）+ `libtv_manifest.json`（机器可读，含 `execution_backend`）+ 参考图清单；由 `build_handoff.py --backend libtv|workbuddy|external` 生成，**纯打包、不生成任何图片视频**。
- 首段必须写死「提示词逐字执行、不得重写 / 扩写 / 翻译」；否则 libtv 后端 Agent 会按自己的习惯重新拆分镜与写 prompt，色场规则全部失效。
- 完成判定：以 `get_agent_status` 回读的 artifacts + 实际导出的成片为准，**派发回执或进度卡不算验收**；成片再跑 `color_field_audit.py`，不达标按「首帧 → 提示词 → 统一调色 → 模型」修。
- 失败 / 超上限 / 平台不支持：停止运行、保留全部产物与日志、把 `run_mode` 切回 `guided` 并从 S5 继续，**不删除任何用户文件**。

## 成果二分交付规范（v3.7 / v3.8）

> **触发条件**：用户反馈「看不懂怎么用」「找不到某个提示词」「哪里是提示词、哪里是注意点」。任一阶段都适用。

项目目录里必须能一眼分清三类东西，**每类只有一个入口**：

| 类型 | 唯一入口文件 | 标记 | 内容 |
|---|---|---|---|
| 🟦 **提示词** | `提示词全集.md` | 标签行 + 三反引号代码块 | 所有可复制的字，按 A 场景 / B 人物 / C 视频 / D 单镜补拍编号 |
| ⚠️ **注意点** | `注意点全集.md` | `Nxx` 编号 | 所有要记住、要检查的坑；每个提示词块下写 `注意点 → Nxx` |
| 📄 **总入口 / 说明 / 数据表** | `000_先看这个-操作手册.md` 等 | 类型标签 | 成果地图、阶段说明、CSV/JSON 数据表 |

五条硬要求：

1. **提示词只在 `提示词全集.md` 里出现一次**；其它文件顶部统一标注「类型：说明 / 数据表，不是提示词」，历史版本标 `⬜ 归档、不作准`，旧代码块前加「勿复制」。
2. **每个提示词块带一行标签**：`🟦 提示词 ｜ 模型 X ｜ 产出 Y ｜ 上传 ✅/❌ ｜ 注意点 Nxx`；「上传」指是否进视频上传序列，不是是否生成。
3. **总入口必须有成果地图**：列出全部文件、每个文件的类型与用途，并直接回答用户问过的「XX 提示词在哪」。
4. **B 段按 `input_mode` 分组，且标明哪组是当前项目要用的**：`B-Z`（`M0` 零素材从零生成：面部 / 服装 / 定妆照 / 概念基调）、`B00`（`M2` 已有资产裁切说明）、`B01`（可选定妆照）、`B02`（三种模式共用的最终拼板）、`B03`（按需材质）、`B04`（组件库）。总入口写一行「本项目 `input_mode=xx`，用 Bxx 段；换主题无资产时从 B-Z 起步」。**不要只给本项目那一组**，否则换主题时文档不可用。
5. **`提示词全集.md` 里的提示词正文一律简体中文（v3.7）**：不做中英双栏、不附英文版、不留英文旧版可复制块。仅平台参数行、资产 ID、器材型号与单位色值、模型专有名保留原文，并在文件头写明这份「保留清单」。Midjourney 的 `--ar / --style / --seed` 单独留在代码块最后一行，不翻译不删除；**`--sref` 自 v3.8 起不再出现在场景图参数行**（只在说明「禁止出现」时写出）。交付前扫全部代码块，出现连续 5 个以上英文单词构成的句子即不合格。细则见 `prompt-playbook.md` §0 第 6 条。

> 场景提示词尤其容易散在多处（旧版可能同时存在 `SCENE_REF` / `SCENE_MOOD` / `SCENE_REVERSE` 三套命名）。统一成一套编号，在总入口用一张表写清「基调版 MJ 出、不上传 / 反打版 NB 出、**可选**」。
> **v4.1 起 `A01–A0N` 恒为「一条通用正文 + N 条场景句组件表」**，不再逐场景各写一整条提示词；`SCENE_REVERSE_0X` 是**可选**步骤，由用户在 S3 自行选择用不用，`guided` 下引导块必须列出这个选项。模板见 `assets/character-sheet-prompts.md` §15.4 / §15.5。

### 阶段闸门补充

- **S3**：默认交付「每人 1 张 `ROLE_SHEET_X` + 拼板 8 项验收」，不是六类实例 + 13 项；`M0` 另加 `B-Z` 从零生成组，`M2` 另加裁切说明。A 段另交 **A08 成品色卡出图提示词**（12 HEX 写死、纯文字出图、A 段取色 + C 段视频共用）、**A01–A0N 一条通用正文 + N 条场景句**、**〔可选〕统一场景反打提示词**、**A09 2 参考标准首帧**（不带色卡）、**A10 `PHOTO_MASTER_01` 摄影母版文字块**（不上传）。引导块必须问「要不要生成场景反打」。

## 9. v5.0 七步引导交付规范（用户 2026-11-08 明确，优先级最高）

### 9.1 一次只给一步

`guided`（默认）下**一次只推进一个大步**，大步内部再拆小步，**每个小步一次选择框**，选完才给下一步；不得提前贴后续大步内容，不得一次倒出全套文档（用户明确说「全部做完」除外，此时仍按大步顺序逐份产出）。

### 9.2 每大步三件套缺一不可

| # | 交付物 | 硬要求 |
|---|---|---|
| ① | 本地**一份** md | 文件名 `第N步_<名称>.md`；只讲这一步；不引用「详见别处」；不出现内部编号；含「这一步做什么 / 你要选的 / 本步成果 / 怎么用 / 回传什么 / 下一步」六节 |
| ② | 对话框 | **直接**把提示词与用法讲清楚，不能只说「已写入文件」；用法一句话讲完：去哪个平台 → 传什么 → 粘框里第几条 → 选几秒档 → 生成几次 → 怎么挑 |
| ③ | **每条一个**粘贴框 | **一条提示词 = 一个独立 fenced code block**，有几条给几个框；**不把多条塞进同一框**、不用分隔行拼接；框上方一行写「第 N 条：用途 \| 模型 \| 产出文件名」；框内只有该条提示词正文与平台参数，不放解释 / 上传顺序 / 验收口径；框外给一句话用法 |

### 9.3 哪些步有粘贴框

| 步 | 有没有生成类提示词 | 给用户什么 |
|---|---|---|
| 0 准备 / 1 视频总规划 / 3 分镜脚本 / 6 自查 | **没有** | 表格与清单，在对话框直接给，不强造提示词 |
| 2 视觉美学基调 / 4 人物场景资产 / 5 视频生成设计 | **有** | 每条提示词各一个粘贴框 + 一句话用法；本地文件按同样顺序逐条逐字存档 |

### 9.4 旧文档先归档再重建

项目目录已有旧版成果时：全部旧 md / csv / json 原样移进 `.backup/旧版完整参考包-<日期>/` → 写一份人话 `README-先看这个.md`（旧包有什么、旧进度在哪、怎么查、怎么回滚）→ 根目录只留 `00_从这里开始.md` 与逐步产出的 `第N步_*.md`。用户 `assets/` 素材与 `.backup/` 不动，**一份都不删**。

### 9.5 与旧阶段表的关系

下表 §1 的 S0–S7 仍是**内部引擎**：状态机 `stage_state.py`、`model_adapter.py`、`build_handoff.py`、`verify_channels.py` 与 `agent-autopilot.md` 全部照旧，硬约束与提示词一字不变。7 大步是**对用户的一层包装**，映射为：0→输入模式盘点、1→S0、2→S0 美学与 S3 色卡/母版、3→S4/S5 分镜与脚本、4→S3 资产、5→S5 视频提示词与 S6 生成、6→S7 验收。**交付时不得把这套映射讲给用户。**

### 9.6 第 3 步分镜表必须含人物层级（v5.1）

用户 2026-11-08 补充「也可以有背景人物，不一定只有她们三个人物，只是这三个人物是主要表现的人物」。因此**第 3 步的分镜成果**除镜号 / 时间 / 场所 / 景别 / 动作外，还要给一张**人物层级表**：主角是唯一被表现、唯一有身份资产的人物；后景焦外可有 1–3 个不具名背景人影，不占参考位、不给正脸与特写、不与主角同焦平面、不产生独立动作线；并在分镜表里标出哪几镜有背景人影、各几人。第 5 步逐镜块按此把背景人影写进背景层与环境动态，【参考绑定】不多挂任何人物资产。**全片不用大远景 / 远景 / 大全景**，景别只在全景及更近档位之间拉开；背景人影只作后景焦外虚化层，不靠拉远镜头去摆；三条铁律其余取值不变。
