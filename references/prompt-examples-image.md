## 0. 通用：把「总揽」翻译成图像提示词

S0 总揽里的每一项都必须变成**可见、可核对**的字段，不写抽象词：

| 总揽项 | 落地写法 |
|---|---|
| 美学设定 | 服装材质、建筑构件、道具清单、圆形锚点、框景物 |
| 色彩氛围 | 主色占比数值 + 8 类载体 + 五级明度阶梯 + 暖冷配比 |
| 光影特点 | 主光方位（高位斜后侧 120–150°）、轮廓光落点、肤色、抬黑、奶油金高光 |
| 整体基调 | 动作速度、景别节奏、留白面积、无对白 |
| 尺度关系 | 道具 1–2 个头宽、建筑 1.5–3 倍人物高、人物占画面高度 1/3–2/3 |

**角色固定描述串**（以下实例里逐字复制、一个字不改）：
`一位年轻药铺学徒，鹅蛋脸、深棕低髻配素色发带、靛蓝棉袍外罩米白围裙、深褐布鞋`
> 定妆图用**固有色**版本（上面这串）；「暖象牙肤色」是成片色场下的肤色，只在 `STANDARD_FRAME_01` 与逐镜提示词里补，不写进定妆图。

## 1. Nano Banana 2 / Pro｜多图编辑型

**能力**：最多 14 张参考（约 10 物件 + 4 角色）、最多约 5 人一致、4K、对话式局部改图、**无负向词字段**。

**写法规则**
1. 导演式白话 brief，不堆形容词。
2. 每个参考给**稳定编号**（`@ROLE_REF_01`），分别写「继承什么 / 不继承什么 / 其余一律不继承」——这是 `awesome-seedance` 的 inherit-nothing-else 写法。
3. 禁项全部改成正向句：不要写「不要文字」，写「画面内不出现任何文字或标记」。
4. 一次只改一个变量：先出 hero frame，再对话式换姿势 / 换场景。
5. **色卡（v4.1）不是风格参考，也不是归纳指令本身**：A08 交付的是把 12 个 HEX 写死的**成品出图提示词**，纯文字出图、不传参考图；那段「请分析这些参考图…」是生成提示词的 meta 指令，只作归纳方法。色卡**两处使用：A 段场景图取色彩方案 + C 段【参考绑定】上传**；标准首帧 / 场景空镜 / 定妆图一律不传色卡、不写 `--sref`，占比数值归色场方案表与摄影母版。

## 2. GPT Image 2 / 2.5｜结构化 / JSON 型

**能力**：最多 10 张参考（按 index 引用）、复杂空间指令、文字渲染、编辑保真。

**写法规则**（`dair-ai` 四要素 + `awesome-gpt-image-2` 的 Prompt-as-Code）
1. **Instruction**「生成一张标准首帧」+ **Context**（色场与参考图职责）+ **Input Data**（人物/道具/布局）+ **Output Indicator**（比例、约束）。
2. 拆成可组合字段：主体 / 布局 / 风格 / 约束，或直接用 JSON。
3. 参考图按 index 写明「这张贡献什么」。
4. 圆形锚点、九宫格覆盖、留白写成**布局字段**，不写成「有层次」。

**完整实例（标准首帧 JSON）**

## 7. 交付前图像层自检（12 项，来自高星仓库做法）

> 第 3、5、7 项只验**成片画面**（标准首帧 / 场景空镜 / 镜头），不要拿去否定合格的影棚定妆图；定妆图按第 11、12 项与 `character-sheet-spec.md` 第 15 节十项单独验。

1. 参考图是否都有稳定编号与「继承/不继承」说明？
2. 角色固定描述串是否逐字一致（无同义词替换）？
3. 主色是否进入 ≥6 类载体、覆盖 3×3 九个分区？
4. 五级明度阶梯是否可指认到具体物件？
5. 是否出现高位斜后侧金色轮廓光 + 正面弱暖补光？
6. 肤色是否保持暖象牙、没被主色染冷？
7. 圆形锚点是否在下三分之一、前景遮挡是否 10–30% 且失焦？
8. 有没有抽象赞美词（epic / 电影感 / 高级感）？有就换成可见物件或数值。
9. 负向词是否按模型机制写（纯名词 / 正向句 / 独立字段 / 完全不写）？
10. 是否配了效果图与记录（seed、参数、参考编号、挑图理由）？
11. **角色参考包**：第一张是否是最先出的 `FACE_QUAD_01` 面部四宫格（四等分、四朝向全为头部特写、无现代浓妆、105mm、低密度黑柔）？后面每张图是否写明引用它哪一格？`ROLE_REF_01` 是否为纯色暖灰影棚 + 三点式 5500K 中性光 + 105mm/85mm+ + 低密度黑柔 + 全身正面全清晰且锁定了 `body_ratio`？是否另出了朝向三视图 `ROLE_TRIVIEW_01`、四格定妆板 `ROLE_BOARD_01` 与六张单图？服装六维与四朝向清单是否写全？
12. **定妆图是否误带成片属性**：有没有主色占比、色卡 `--sref`、成片暖逆光或金色轮廓光、彩色灯光、失焦前景、留白、景深虚化？有一项即重出。注意三点式 5500K 中性白棚光里的窄轮廓光是允许的，不算误带。

## 7. v4.1 图像层色卡与场景提示词边界（覆盖本文旧版写法）

| 步骤 | 旧写法（作废） | v3.8 写法 |
|---|---|---|
| 视觉母版 / 场景基调图 | 用 `--sref` 把整张色卡当风格垫图 | **场景基调图同传色卡取色彩方案（正文限定只取 12 色）、不写 `--sref`**；`A00` 母版不挂色卡；颜色与光位写进正文 |
| 色卡生成 | 从单张母版取色、手填三段占比色块 / 把「归纳指令」原样当出图提示词 / 同传多图出图 | **两步走**：按 12 色归纳 meta 指令对参考素材实际归纳 + 分组检查 → 把 12 个 HEX 写死成**纯文字成品出图提示词**，不传参考图 |
| 色卡使用 | 标准首帧 / 场景空镜当风格参考 | **A 段场景图取色彩方案 + C 段视频【参考绑定】上传**（标准首帧仍不带色卡） |
| 标准首帧 | ≥6 参考同传且含色卡 | 默认 **2 参考**（`ROLE_SHEET_<主角>` + 场景参考 1 张；`SCENE_REVERSE_01` 或 `SCENE_MOOD_01`），不带色卡 |
| 场景基调图提示词 | 每场景各写一整条完整提示词、重复占比与光位 | **一条通用正文 + N 条场景句组件表**，共用 `--seed`；占比等验收口径不进代码块 |
| 场景反打 | 每场景 A/B 两套、必传 | **一条统一反打提示词、可选**；不用时删 C 段引用、首帧第 2 张换 `SCENE_MOOD_01` |
| 占比来源 | 色卡 | 色场方案表 + `PHOTO_MASTER_01`【光影色彩】 |

色卡固定提示词与分组检查见 `color-system.md` §7；视频六块结构、摄影母版与上传序列见 `prompt-examples-video.md` §8。
